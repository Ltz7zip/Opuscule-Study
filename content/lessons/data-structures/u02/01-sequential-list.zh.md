## 本讲目标

学完这一讲，你能由地址公式算出任意元素的存储位置，能推出插入与删除的平均移动次数，能解释顺序表为什么查询快而增删慢，并能在静态分配与动态扩容之间做出选择。

## 三行回顾

- 顺序表用一组地址连续的存储单元依次存放线性表元素，逻辑相邻即物理相邻。
- 随机访问是 $O(1)$，插入删除要移动元素，平均约 $n/2$ 次。
- 静态数组容量固定，动态数组按倍数扩容，摊还代价仍是 $O(1)$。

## 地址公式与随机访问

顺序表把 $(a_1,a_2,\dots,a_n)$ 放进连续空间。设首元素地址为 $\mathrm{LOC}(a_1)$，每个元素占 $L$ 字节，则第 $i$ 个元素的地址是

$$
\mathrm{LOC}(a_i)=\mathrm{LOC}(a_1)+(i-1)\times L
$$

取 $\mathrm{LOC}(a_1)=1000$、$L=4$，则 $a_5$ 在 $1000+4\times4=1016$。这个式子是等时的：不管 $i$ 是 1 还是 $10^{6}$，一次乘法一次加法就到，所以按位序取值是 $O(1)$。

C 语言里用结构体把「数组 + 当前长度 + 容量」绑在一起：

```c
#define MAXSIZE 100
typedef struct {
    int data[MAXSIZE];
    int length;
} SqList;
```

`length` 必须单独记录，因为数组容量和表长是两回事：容量 100 的表，长度可以是 0 到 100 之间的任何值。

## 插入与删除的代价

在第 $i$ 个位置插入，需要把 $a_i..a_n$ 整体后移一位，移动 $n-i+1$ 个元素。表尾插入（$i=n+1$）移动 0 个，表头插入移动 $n$ 个。假设 $n+1$ 个插入位置等概率，平均移动次数为

$$
E_{\text{ins}}=\frac{1}{n+1}\sum_{i=1}^{n+1}(n-i+1)=\frac{1}{n+1}\cdot\frac{n(n+1)}{2}=\frac{n}{2}
$$

删除第 $i$ 个元素要把 $a_{i+1}..a_n$ 前移，移动 $n-i$ 个。$n$ 个位置等概率时

$$
E_{\text{del}}=\frac{1}{n}\sum_{i=1}^{n}(n-i)=\frac{n-1}{2}
$$

取 $n=10$：插入平均移 5 个，删除平均移 4.5 个。数量级都是 $O(n)$，与「查询 $O(1)$」形成对照。

| 操作 | 最好 | 最坏 | 平均 | 是否移动元素 |
| --- | --- | --- | --- | --- |
| 按位序取值 | $O(1)$ | $O(1)$ | $O(1)$ | 否 |
| 按值查找 | $O(1)$ | $O(n)$ | $O(n)$ | 否 |
| 插入 | $O(1)$ | $O(n)$ | $O(n)$ | 是 |
| 删除 | $O(1)$ | $O(n)$ | $O(n)$ | 是 |

> [!NOTE]
> 平均移动次数里的分母是「合法位置数」：插入有 $n+1$ 个位置（含表尾之后），删除只有 $n$ 个位置。分母写错，$n/2$ 与 $(n-1)/2$ 就会互相混淆。

## 动态分配与取舍

静态数组写死 `MAXSIZE`，估小了溢出，估大了浪费。动态顺序表在容量用满时申请一块更大的连续空间并整体搬迁：

```c
typedef struct {
    int *data;
    int length, capacity;
} DynList;

int grow(DynList *L) {
    int *p = malloc(L->capacity * 2 * sizeof(int));
    if (!p) return 0;
    for (int i = 0; i < L->length; i++) p[i] = L->data[i];
    free(L->data);
    L->data = p;
    L->capacity *= 2;
    return 1;
}
```

容量按 2 倍增长时，插入 $n$ 个元素的总搬迁量是 $1+2+4+\dots+n<2n$，摊到每次插入是常数，所以「动态数组尾部追加」的摊还复杂度是 $O(1)$。但单次扩容仍是 $O(n)$，对实时性敏感的场合要预留容量。

顺序表的优点是存储密度为 1、支持随机访问、缓存友好；缺点是需要一整块连续空间、增删要移动、容量管理麻烦。元素基本不动、以查询为主时选它；频繁在中间增删时应该换链表。

## 三个常见误解

> [!MYTH] 顺序表就是数组。
> 数组只是存储载体。顺序表是「数组 + 长度」的抽象数据类型，长度字段决定了合法访问范围，越界读写不是顺序表允许的操作。

> [!MYTH] 插入平均移动 $n/2$ 个元素，所以复杂度是 $O(n/2)$。
> 渐进记号丢掉常数系数，$O(n/2)=O(n)$。反过来，写 $O(n/2)$ 不算错，只是不规范。

> [!MYTH] 顺序表删除只要把长度减一。
> 长度减一只在删除表尾时成立。删除中间元素必须把后面的元素前移，否则表里会留下空洞。

## 练习

> [!PRACTICE] 1 · 算地址
> 顺序表首地址 2000，元素占 8 字节，求 $a_7$ 的地址；若表长 20，删除 $a_3$ 要移动几个元素？
>
> > [!ANSWER] 看答案
> > $2000+(7-1)\times8=2048$。删除 $a_3$ 需移动 $20-3=17$ 个元素。

> [!PRACTICE] 2 · 推平均
> 若只在表头或表尾插入且概率各半，平均移动次数是多少？
>
> > [!ANSWER] 看答案
> > 表头移 $n$ 个，表尾移 0 个，期望为 $n/2$。等概率假设变了，平均值就变，但阶不变。

> [!PRACTICE] 3 · 扩容
> 动态表从容量 1 开始每次翻倍，插入 $n=8$ 个元素共搬迁多少次？
>
> > [!ANSWER] 看答案
> > 容量 1→2→4→8 各搬迁一次，共 $1+2+4=7$ 次，小于 $2n=16$。

## 严格表述

顺序表是线性表的顺序存储表示：用一组地址连续的存储单元依次存放表中元素，元素 $a_i$ 的地址为 $\mathrm{LOC}(a_1)+(i-1)L$，故按位序存取的时间为 $O(1)$。在长度为 $n$ 的顺序表第 $i$ 个位置插入需移动 $n-i+1$ 个元素，等概率假设下平均移动 $n/2$ 个；删除第 $i$ 个元素需移动 $n-i$ 个，平均移动 $(n-1)/2$ 个，两者时间均为 $O(n)$。顺序表的存储密度为 1，但要求连续的存储空间，容量固定或需整体搬迁扩容。
