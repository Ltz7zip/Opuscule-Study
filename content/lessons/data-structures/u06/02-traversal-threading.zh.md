## 本讲目标

学完这一讲，你能写出先序、中序、后序三种递归遍历并给出结果，能由先序加中序唯一还原一棵二叉树，能看懂中序线索化代码并说出每个空指针被改写成了谁。

## 三行回顾

- 遍历是按某条搜索路径访问每个结点恰好一次，先中后的区别只在「根」被访问的时机。
- 先序加中序、后序加中序可以唯一确定二叉树，先序加后序不行。
- 线索化把空指针改成指向前驱或后继的线索，使遍历无需栈。

## 四种遍历与递归代码

以树 $A(B(D,E),C(F,G(H)))$ 为例，即 $A$ 的左孩子 $B$ 带 $D$、$E$，右孩子 $C$ 带 $F$ 和 $G$，$G$ 只有左孩子 $H$。

```c
void PreOrder(BiTree T) {
    if (!T) return;
    visit(T);
    PreOrder(T->lchild);
    PreOrder(T->rchild);
}
```

把 `visit(T)` 在三行之间的位置移动，就得到另外两种：放在两次递归之间是中序，放在两次递归之后是后序。递归代码的差别只有一行，结果却完全不同。

| 遍历 | 访问根的时机 | 序列 |
| --- | --- | --- |
| 先序 | 进入子树时 | A B D E C F G H |
| 中序 | 左子树之后 | D B E A F C H G |
| 后序 | 两棵子树之后 | D E B F H G C A |
| 层次 | 按层从左到右 | A B C D E F G H |

手算时抓住三条口径：先序是「根—左—右」，中序是「左—根—右」，后序是「左—右—根」。以中序为例，整棵树先走完左子树（$D,B,E$），再访问根 $A$，最后走右子树；右子树里先走 $F$，再访问 $C$，最后走 $G$ 的子树，而 $G$ 只有左孩子，故先 $H$ 后 $G$，得到 $F,C,H,G$。

层次遍历用队列而非递归：根入队，每次出队一个结点就访问它并把非空孩子入队，直到队空。它按距离根的层数推进，是求树宽、判断完全性的基础。

## 由遍历序列还原二叉树

已知先序与中序，可唯一还原：先序的第一个字符必是根；在中序中找到它，左边是该根的左子树结点集，右边是右子树结点集；再按这两个集合的大小切分先序序列，递归即可。

以上面的树验证一次。先序 $A|BDE|CFGH$，中序 $DBE|A|FCHG$。

- 根为 $A$，中序左侧 $DBE$（3 个）、右侧 $FCHG$（4 个）。
- 左子树先序 $BDE$、中序 $DBE$：根为 $B$，左侧 $D$、右侧 $E$，得 $B(D,E)$。
- 右子树先序 $CFGH$、中序 $FCHG$：根为 $C$，左侧 $F$、右侧 $HG$。
- $HG$ 的先序为 $GH$，中序为 $HG$：根为 $G$，左侧 $H$，右侧空，得 $G(H)$。

拼起来正好回到 $A(B(D,E),C(F,G(H)))$。

为什么先序加后序不够？两者都只能确定根，无法区分「只有一个孩子时它在左还是在右」。例如 $X(Y)$ 与 $X(\ ,Y)$ 的先序都是 $XY$、后序都是 $YX$，却对应两棵不同的树。中序提供了左右的分界线，所以必须搭配中序。

| 已知序列 | 能否唯一还原 |
| --- | --- |
| 先序 + 中序 | 能 |
| 后序 + 中序 | 能 |
| 层次 + 中序 | 能 |
| 先序 + 后序 | 不能 |

## 中序线索化

$n$ 个结点的二叉链表有 $n+1$ 个空指针。线索化把它们改造成指向前驱或后继的指针，并增设 `ltag`、`rtag` 区分「孩子」与「线索」：

```c
typedef struct ThreadNode {
    int data;
    struct ThreadNode *lchild, *rchild;
    int ltag, rtag;      /* 1 表示线索 */
} ThreadNode, *ThreadTree;

void InThread(ThreadTree p, ThreadTree *pre) {
    if (!p) return;
    InThread(p->lchild, pre);
    if (!p->lchild) { p->lchild = *pre; p->ltag = 1; }
    if (*pre && !(*pre)->rchild) { (*pre)->rchild = p; (*pre)->rtag = 1; }
    *pre = p;
    InThread(p->rchild, pre);
}
```

`pre` 始终指向上一个被访问的结点，因此左空指针能立刻指向前驱，而右空指针要等到访问下一个结点时才被填上。

对 $A(B(D,E),C(F,G(H)))$ 做中序线索化。中序序列为 $D,B,E,A,F,C,H,G$，按下标记 $1..8$：

| 结点 | 空指针 | 线索指向 | 说明 |
| --- | --- | --- | --- |
| $D$ | 左、右 | 无、$B$ | 首结点无前驱 |
| $E$ | 左、右 | $B$、$A$ | 前驱后继都在同层 |
| $F$ | 左、右 | $A$、$C$ | 跨越子树 |
| $H$ | 左、右 | $C$、$G$ | 前驱在祖先链上 |
| $G$ | 右 | $-$、无 | 末结点无后继 |

线索化之后，中序遍历不必递归也不必栈：从左下角出发，沿右线索走；遇到 `rtag == 0` 的结点，就进入其右子树再一路向左下。整个过程每个结点访问一次，时间 $O(n)$，额外空间 $O(1)$——这正是牺牲两个标志位换来的收益。

> [!NOTE]
> 线索化改变的是空指针的语义，不改变树的逻辑结构。访问孩子前必须先看 `ltag`：若为 1，`lchild` 指向的是前驱而不是左孩子，直接当孩子用会走进遍历序列的错误位置。

## 三个常见误解

> [!MYTH] 三种遍历只是打印顺序不同，作用一样。
> 中序对二叉排序树给出有序序列，后序适合先处理孩子再处理父结点的场景（如释放整棵树、计算表达式），先序适合复制结构。用途由访问根的时机决定。

> [!MYTH] 已知先序和后序就能还原二叉树。
> 不能。单孩子结点无法判断孩子在哪一侧，会得到多棵不同的树。必须搭配中序。

> [!MYTH] 线索二叉树就是给孩子指针加了标记。
> 标记的意义在于重新定义空指针的用途：它们存放的是遍历序列中的前驱与后继，属于额外的结构信息，而不是孩子关系。

## 练习

> [!PRACTICE] 1 · 写序列
> 树 $A(B(D,E),C(F,G(H)))$ 的后序序列是什么？写出第三步的位置。
>
> > [!ANSWER] 看答案
> > D E B F H G C A。后序最后访问的是根 $A$。

> [!PRACTICE] 2 · 还原
> 先序 $ABDEC$、中序 $DBEAC$，画出这棵树。
>
> > [!ANSWER] 看答案
> > 根 $A$，左子树 $B(D,E)$，右子树只有 $C$，即 $A(B(D,E),C)$。

> [!PRACTICE] 3 · 数线索
> 有 10 个结点的二叉树，中序线索化后有多少个线索？
>
> > [!ANSWER] 看答案
> > 空指针共 $n+1=11$ 个，全部改造成线索，故有 11 条线索。

## 严格表述

二叉树的遍历是按某条搜索路径访问每个结点且仅访问一次的过程，按访问根的时机分为先序、中序、后序三种深度优先次序，另有按层推进的层次遍历。先序为根、左、右，中序为左、根、右，后序为左、右、根。给定先序与中序序列，或后序与中序序列，或层次与中序序列，可唯一确定一棵二叉树；仅由先序与后序不能，因为单孩子结点的分支方向无法判定。线索二叉树利用二叉链表中 $n+1$ 个空指针域，将其改写为指向遍历序列中前驱与后继的线索，并以 `ltag`、`rtag` 标志位区分线索与孩子指针；中序线索化后可在 $O(1)$ 辅助空间内完成中序遍历。线索化不改变树的逻辑结构，仅改变空指针的语义。
