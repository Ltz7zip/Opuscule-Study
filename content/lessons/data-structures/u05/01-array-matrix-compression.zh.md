## 本讲目标

学完这一讲，你能按行优先与列优先写出任意维数组的地址公式，能推导对称矩阵下三角的一维下标映射，能判断三角矩阵与稀疏矩阵该用哪种压缩表示。

## 三行回顾

- 数组是下标与值的映射，多维数组在内存中按某种次序线性化。
- 按行优先的下标公式决定一切，转置就是把两个系数调换。
- 对称矩阵只需存一半，稀疏矩阵只存非零元与位置。

## 多维数组的地址计算

一维数组的地址是 $\mathrm{LOC}(a_i)=\mathrm{LOC}(a_0)+i\times L$。二维数组 $A[m][n]$ 在内存里必须排成一维，于是产生两种次序。按行优先（C、Pascal 采用）先排完第 0 行再排第 1 行：

$$
\mathrm{LOC}(i,j)=\mathrm{LOC}(0,0)+(i\times n+j)\times L
$$

按列优先（Fortran 采用）先排完第 0 列再排第 1 列：

$$
\mathrm{LOC}(i,j)=\mathrm{LOC}(0,0)+(j\times m+i)\times L
$$

取 $A[4][5]$、$L=4$、$\mathrm{LOC}(0,0)=1000$，求 $A[2][3]$。按行优先：$1000+(2\times5+3)\times4=1052$。按列优先：$1000+(3\times4+2)\times4=1056$。两者差 4 个字节，正好是「同一元素在两种次序下前面排了多少个」的差。

| 次序 | 公式 | 相邻元素地址差 | 典型语言 |
| --- | --- | --- | --- |
| 行优先 | $(i\times n+j)L$ | 同一行内差 $L$ | C、Pascal |
| 列优先 | $(j\times m+i)L$ | 同一列内差 $L$ | Fortran |

三维数组 $A[p][m][n]$ 按行优先时，下标 $(i,j,k)$ 的偏移为 $(i\times m\times n+j\times n+k)\times L$。规律很清楚：每一维的系数等于它右边所有维度长度的乘积。

## 对称矩阵与三角矩阵的压缩

$n$ 阶对称矩阵满足 $a_{ij}=a_{ji}$，只需存下三角（含对角线）共 $n(n+1)/2$ 个元素，空间从 $n^{2}$ 降到约 $n^{2}/2$。按行优先把下三角排进一维数组，下标从 0 开始：

$$
k=\frac{i(i+1)}{2}+j,\qquad i\ge j
$$

第 $i$ 行之前有 $0+1+\dots+i=\dfrac{i(i+1)}{2}$ 个元素，加上本行的第 $j$ 个，就是上式。取 $n=5$、元素 $(3,2)$：$k=3\times4/2+2=8$。若访问的是上三角的 $(2,3)$，利用对称性换成 $(3,2)$，同样得到 8。

| 矩阵类型 | 非零元个数 | 存储量 | 下标映射 |
| --- | --- | --- | --- |
| 一般 $n$ 阶 | $n^{2}$ | $n^{2}$ | $i\times n+j$ |
| 对称 | $n(n+1)/2$ | $n(n+1)/2$ | $i(i+1)/2+j$ |
| 下三角 | $n(n+1)/2$ | $n(n+1)/2$ | $i(i+1)/2+j$ |
| 上三角 | $n(n+1)/2$ | $n(n+1)/2$ | 按行存时需另推 |

上三角按行存储时，第 $i$ 行只有 $n-i$ 个元素，前 $i$ 行共 $\sum_{t=0}^{i-1}(n-t)=i\,n-\dfrac{i(i-1)}{2}$ 个，于是 $k=i\,n-\dfrac{i(i-1)}{2}+(j-i)$。可见公式不是背下来的，而是数「前面已经排了多少个」。

对三角矩阵（一半是常数 $c$），存储量仍是 $n(n+1)/2+1$，多出的一个单元放常数，访问另一半时直接返回它，无需分支判断具体值。

## 稀疏矩阵的表示

稀疏矩阵的非零元很少（通常少于 5%），若仍按二维数组存，绝大多数单元是 0。三元组表只存非零元的行、列、值：

```c
typedef struct {
    int i, j;
    int e;
} Triple;

typedef struct {
    Triple data[1000];
    int mu, nu, tu;      /* 行数、列数、非零元个数 */
} TSMatrix;
```

三元组表节省空间，但按行随机访问能力丧失：要找 $(i,j)$ 得线性扫描。转置时若逐列扫描，代价是 $O(\text{nu}\times\text{tu})$；用「列计数 + 起始位置」两趟扫描可降到 $O(\text{nu}+\text{tu})$。

十字链表适合非零元会动态变化的场合。每个非零元结点同时挂在两个链上：

```c
typedef struct OLNode {
    int i, j, e;
    struct OLNode *right, *down;
} OLNode, *OLink;
```

`right` 串起同一行的下一个非零元，`down` 串起同一列的下一个非零元，另设行头指针数组与列头指针数组。插入删除只改局部指针，不必像三元组表那样整体搬移，代价是每个结点多两个指针。

> [!NOTE]
> 压缩的本质是「改变下标映射」，不是「减少运算」。数组的随机访问之所以还是 $O(1)$，是因为映射公式仍是一次乘法加法；一旦改用链表，定位就退化为 $O(\text{行内非零元数})$。

## 三个常见误解

> [!MYTH] 二维数组在内存里就是二维的。
> 内存是一维的。所谓二维只是映射公式带来的错觉，行优先与列优先是两种不同的线性化次序，混用会读出错位的数据。

> [!MYTH] 对称矩阵压缩后不能随机访问。
> 能。只要把 $(i,j)$ 通过 $k=i(i+1)/2+j$ 映射到一维下标，访问仍是 $O(1)$，对称位置交换下标即可。

> [!MYTH] 稀疏矩阵用三元组表一定比十字链表好。
> 三元组表省指针、适合静态矩阵；十字链表适合频繁插入删除。结构选择取决于操作，而不是非零元的比例。

## 练习

> [!PRACTICE] 1 · 算地址
> $A[6][8]$ 按行优先存放，$L=2$，$\mathrm{LOC}(0,0)=500$，求 $A[4][5]$ 的地址。
>
> > [!ANSWER] 看答案
> > $500+(4\times8+5)\times2=500+74=574$。

> [!PRACTICE] 2 · 算下标
> 5 阶对称矩阵按行存下三角，求 $(4,1)$ 的一维下标。
>
> > [!ANSWER] 看答案
> > $k=4\times5/2+1=11$，即第 12 个元素。

> [!PRACTICE] 3 · 选结构
> 一个 $1000\times1000$ 的矩阵有 2000 个非零元，需要频繁按行遍历并偶尔插入新非零元，选三元组表还是十字链表？
>
> > [!ANSWER] 看答案
> > 十字链表。非零元仅 0.2%，插入频繁，链式结构改局部指针即可；三元组表插入要整体搬移。

## 严格表述

数组是下标集合到值集合的映射。多维数组在内存中按行优先或列优先线性化：$m\times n$ 数组按行优先时元素 $(i,j)$ 的地址为 $\mathrm{LOC}(0,0)+(in+j)L$，按列优先时为 $\mathrm{LOC}(0,0)+(jm+i)L$，其中 $L$ 为元素所占字节数。$n$ 阶对称矩阵仅需存储下三角的 $n(n+1)/2$ 个元素，按行优先时 $(i,j)$ 映射为 $k=i(i+1)/2+j$；上三角按行存储时映射为 $k=in-i(i-1)/2+(j-i)$。三角矩阵另以一个单元存放常数。稀疏矩阵可采用三元组表，以（行，列，值）记录非零元，空间为 $O(t)$ 但丧失随机定位；也可采用十字链表，每个非零元结点同时链入所在行与列，支持 $O(1)$ 局部插入与删除，代价是额外的指针开销。
