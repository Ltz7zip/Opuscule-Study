## 本讲目标

学完这一讲，你能说清串与线性表的异同，能选择定长顺序、堆分配或块链三种存储，能手推朴素匹配的比较次数，并能指出它在什么输入上退化到最坏情况。

## 三行回顾

- 串是元素限定为字符的线性表，操作以「子串」为单位而不是单个字符。
- 定长顺序存储简单但会截断，堆分配按需申请，块链存储适合超长串。
- 朴素匹配逐位对齐、失配即回溯，最坏比较次数为 $(n-m+1)\times m$。

## 串的三种存储

串的逻辑结构与线性表相同，差别在操作粒度：线性表常按位置存取单个元素，串则常做拼接、取子串、定位。存储上有三种主流方案。

定长顺序存储用字符数组，末尾不依赖 `'\0'` 而另设长度：

```c
#define MAXLEN 255
typedef struct {
    char ch[MAXLEN];
    int length;
} SString;
```

它的缺点写死在 `MAXLEN` 里：超过长度的部分被截断，且截断往往不报错，只在结果里悄悄少几个字符。

堆分配存储在运行时按串长申请空间，长度可变：

```c
typedef struct {
    char *ch;
    int length;
} HString;
```

块链存储把串切成若干块，每块存多个字符，块间用指针相连。它适合无法一次分配大块连续内存的超长串，但随机取子串要跨块拼接，实现更复杂。

| 存储方式 | 空间 | 取子串 | 适用场景 |
| --- | --- | --- | --- |
| 定长顺序 | 固定 | $O(m)$ | 长度已知且较短 |
| 堆分配 | 按需 | $O(m)$ | 一般场合，长度可变 |
| 块链 | 按块申请 | $O(m)$ 但常数大 | 超长串、内存碎片化 |

## 朴素模式匹配

问题：在主串 $S$（长度 $n$）中找模式串 $T$（长度 $m$）第一次出现的位置。朴素算法把 $T$ 的第 1 个字符对齐到 $S$ 的第 1 个字符，逐位比较；一旦失配，就把 $T$ 整体右移一位，从 $S$ 的下一个字符重新开始。

```c
int Index(SString S, SString T) {
    int i = 1, j = 1;
    while (i <= S.length && j <= T.length) {
        if (S.ch[i-1] == T.ch[j-1]) { i++; j++; }
        else { i = i - j + 2; j = 1; }   /* 回溯到本轮起点的下一位 */
    }
    if (j > T.length) return i - T.length;
    return 0;
}
```

回溯式 `i = i - j + 2` 是全部精髓：$i-j$ 是本轮对齐的起点，加 2 得到下一位。这条语句把已经比较过的信息全部丢弃，也正是 KMP 要改进的地方。

取 $S=\text{"aaaaaab"}$、$T=\text{"aaab"}$，$n=7$、$m=4$，共 4 个对齐位置：

| 对齐位置 | 比较过程 | 比较次数 | 结果 |
| --- | --- | --- | --- |
| 1 | a=a, a=a, a=a, a≠b | 4 | 失配 |
| 2 | a=a, a=a, a≠b | 4 | 失配 |
| 3 | a=a, a≠b | 4 | 失配 |
| 4 | a=a, a=a, a=a, b=b | 4 | 成功 |

虽然第 1 个对齐位置在第 4 个字符就失配，但每次都要先比较前 3 个相同的 `a`。四次对齐共 $4\times4=16$ 次比较，恰为 $(n-m+1)\times m=(7-4+1)\times4=16$。

## 朴素匹配的代价

最好情况是第一个对齐位置就匹配成功或首字符即失配，比较 $m$ 次或 $n-m+1$ 次，都是 $O(n+m)$ 量级。最坏情况出现在「主串与模式串前 $m-1$ 个字符全部相同、最后一个不同」的输入上，每一次对齐都要比较满 $m$ 个字符才失败，总次数

$$
T_{\text{worst}}=(n-m+1)\times m
$$

当 $m\approx n/2$ 时约为 $n^{2}/4$，即 $O(nm)$。这类输入并不罕见：DNA 序列、日志中大量重复的分隔符、连续空格文本，都会制造长前缀。

| 情况 | 比较次数 | 例子 |
| --- | --- | --- |
| 最好 | $m$ | $S=\text{"aaab"}$，$T=\text{"aaab"}$ |
| 一般 | 介于两者之间 | 随机字符 |
| 最坏 | $(n-m+1)m$ | $S=\text{"aaaaaab"}$，$T=\text{"aaab"}$ |

改进方向有两条：一是预处理模式串，利用已匹配前缀的信息避免回溯主串指针，这就是 KMP；二是用哈希把子串比较降到 $O(1)$，即 Rabin-Karp。两者的共同点是——不再无偿丢弃已经比较过的字符。

> [!NOTE]
> 复杂度里的 $n$ 与 $m$ 是两个独立规模，不能像单参数问题那样只写 $O(n^{2})$。写 $O(nm)$ 才表达了「模式串变长会变慢」这一事实。

## 三个常见误解

> [!MYTH] 串就是字符数组。
> 字符数组只是存储形式。串的抽象类型以子串为单位定义操作，长度、拼接、定位的语义都不属于数组。

> [!MYTH] 朴素匹配平均很快，所以最坏情况可以忽略。
> 在重复字符多的真实数据上最坏情况经常发生。文本编辑器查找、入侵检测的特征匹配都不能接受 $O(nm)$ 的退化。

> [!MYTH] 失配后模式串要右移 $m$ 位。
> 朴素算法只右移一位。右移更多位需要证明被跳过的位置不可能匹配，这正是 KMP 的 `next` 数组提供的信息。

## 练习

> [!PRACTICE] 1 · 数比较
> $S=\text{"abababa"}$，$T=\text{"aba"}$，朴素匹配共比较多少次？
>
> > [!ANSWER] 看答案
> > 第 1 个对齐位置即匹配成功，比较 3 次，返回位置 1。

> [!PRACTICE] 2 · 构造最坏
> $n=10$、$m=5$，写出一个使比较次数达到 30 的主串与模式串。
>
> > [!ANSWER] 看答案
> > $S=\text{"aaaaaaaaab"}$，$T=\text{"aaaab"}$。6 个对齐位置各比较 5 次，共 30 次。

> [!PRACTICE] 3 · 选存储
> 需要读取一个 2 GB 的日志文件并反复取子串，选哪种存储？为什么？
>
> > [!ANSWER] 看答案
> > 块链存储。2 GB 很难保证一整块连续内存，块链按块申请可避开分配失败；代价是取子串要跨块拼接。

## 严格表述

串是由零个或多个字符组成的有限序列，其逻辑结构为线性表，元素限定为字符。常见存储表示有三种：定长顺序存储以固定长度数组存放字符并另设长度字段，超出部分被截断；堆分配存储在运行时按串长申请连续空间，长度可变；块链存储将串划分为若干块并以指针链接，适用于超长串。朴素模式匹配将模式串 $T$ 依次对齐到主串 $S$ 的每个位置，逐字符比较，失配时模式串右移一位、主串指针回溯至本轮起点的下一位，最坏比较次数为 $(n-m+1)m$，时间 $O(nm)$；最好情况为 $O(m)$。该算法不利用已匹配前缀的信息，因而是后续 KMP 算法的改进起点。
