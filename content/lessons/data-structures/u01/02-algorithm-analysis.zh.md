## 本讲目标

学完这一讲，你能判断一段代码是不是算法，能逐行数出它的基本语句执行次数 $T(n)$，能用 $O$、$\Omega$、$\Theta$ 三个记号写出结论，并分清时间开销与空间开销各自该记在谁头上。

## 三行回顾

- 算法是求解问题的一系列明确指令，必须满足有穷、确定、可行、有输入、有输出。
- 时间复杂度不是秒数，而是基本语句执行次数随规模 $n$ 增长的阶。
- 渐进记号只保留增长最快的项，并丢掉常数系数。

## 算法的五个特性与评价标准

一个过程要成为算法，需要同时满足五条：

| 特性 | 含义 | 反例 |
| --- | --- | --- |
| 有穷性 | 有限步内结束 | `while (1) {}` |
| 确定性 | 每条指令无歧义 | 未初始化的变量参与判断 |
| 可行性 | 每步都能由基本运算实现 | 直接调用不存在的库函数 |
| 输入 | 零个或多个输入 | 不读任何参数却声称在求解 |
| 输出 | 至少一个输出 | 算完不返回、不打印 |

评价一个算法，通常看正确性、可读性、健壮性和效率。前三条靠测试与代码审查保证，效率则要用数量级来度量，因为同一段代码在不同机器上的秒数不可比。

## 逐行数清一段代码

考虑下面这段求双重和的代码：

```c
int sum(int n) {
    int s = 0;                          /* 1 次 */
    for (int i = 1; i <= n; i++)        /* 判断 n+1 次 */
        for (int j = 1; j <= i; j++)    /* 内层判断 sum(i+1) 次 */
            s += i * j;                 /* 执行 sum(i) 次 */
    return s;                           /* 1 次 */
}
```

把每条基本语句的次数相加。内层循环对固定的 $i$ 执行 $i$ 次赋值、判断 $i+1$ 次，于是

$$
T(n)=1+(n+1)+\sum_{i=1}^{n}(i+1)+\sum_{i=1}^{n}i+1
$$

用 $\sum_{i=1}^{n}i=\dfrac{n(n+1)}{2}$ 化简：

$$
T(n)=n+3+2\cdot\frac{n(n+1)}{2}=n^{2}+3n+3
$$

当 $n=100$ 时 $T=10303$；当 $n=1000$ 时 $T=1003003$。$n$ 扩大 10 倍，次数约扩大 100 倍，二次项完全主导，因此写成 $T(n)=O(n^{2})$。

换一段代码，结论会立刻不同：

```c
for (int i = 1; i <= n; i *= 2)
    s += i;
```

`i` 依次取 $1,2,4,\dots,2^{k}$，循环在 $2^{k}>n$ 时停止，执行次数为 $\lfloor\log_2 n\rfloor+1$，即 $O(\log n)$。嵌套层数不等于复杂度，循环变量的变化方式才决定阶。

常见阶的增长速度如下，取 $n=10^{6}$：

| 阶 | 名称 | $n=10^{6}$ 时的量级 |
| --- | --- | --- |
| $O(1)$ | 常数 | 1 |
| $O(\log n)$ | 对数 | 约 20 |
| $O(n)$ | 线性 | $10^{6}$ |
| $O(n\log n)$ | 线性对数 | 约 $2\times10^{7}$ |
| $O(n^{2})$ | 平方 | $10^{12}$ |

## 空间复杂度与渐进记号

空间复杂度 $S(n)$ 统计算法在运行过程中除输入外额外占用的存储单元。原地交换两个变量只用常数个临时单元，$S(n)=O(1)$；把 $n$ 个元素复制一份再排序，$S(n)=O(n)$；递归深度为 $n$ 的函数，每一层都要压栈，$S(n)=O(n)$。递归算法的时间与空间要分开算，不能因为代码只有几行就认为两者都小。

四个记号的区别在于给出的是上界、下界还是紧界：

| 记号 | 含义 | 例子 |
| --- | --- | --- |
| $O$ | 渐近上界：存在 $c>0$ 使 $T(n)\le c\,g(n)$ | $3n^{2}+5n+2=O(n^{2})$ |
| $\Omega$ | 渐近下界：存在 $c>0$ 使 $T(n)\ge c\,g(n)$ | $3n^{2}+5n+2=\Omega(n^{2})$ |
| $\Theta$ | 紧界：同时是 $O$ 与 $\Omega$ | $3n^{2}+5n+2=\Theta(n^{2})$ |
| $o$ | 严格低阶：$T(n)/g(n)\to 0$ | $n=o(n^{2})$ |

教材在分析算法时默认使用 $O$，因为它回答「最坏要花多少」。但说「插入排序是 $O(n^{2})$」并不排除它在有序输入上只需 $O(n)$，上界不唯一，紧界才唯一。

> [!NOTE]
> 数复杂度时只数最内层被反复执行的语句，外层循环的初始化与判断贡献的是低阶项，化简后会被丢掉。但推导过程要写全，否则容易把 $n^{2}/2$ 错记成 $n/2$。

## 三个常见误解

> [!MYTH] $O(1)$ 表示只执行一次。
> 它表示执行次数与 $n$ 无关。循环 100 次的固定长度循环仍是 $O(1)$。

> [!MYTH] 时间复杂度就是程序跑多少秒。
> 秒数依赖机器、编译器和输入。复杂度只描述增长趋势，是同一条曲线在不同 $n$ 下的形状。

> [!MYTH] 两层嵌套循环一定是 $O(n^{2})$。
> 若内层从 $i$ 开始，总次数是 $n(n+1)/2$，仍是 $O(n^{2})$；但若内层每次减半，总次数会变成 $O(n\log n)$，阶由步长决定。

## 练习

> [!PRACTICE] 1 · 照着做
> 求 `for (i=1;i<=n;i++) for (j=1;j<=n;j++) a[i][j]=0;` 的 $T(n)$。
>
> > [!ANSWER] 看答案
> > 外层 $n$ 次，内层每次 $n$ 次赋值，共 $n^{2}$ 次，$T(n)=O(n^{2})$。

> [!PRACTICE] 2 · 变式
> 把内层改成 `for (j=i;j<=n;j++)`，复杂度变不变？给出精确次数。
>
> > [!ANSWER] 看答案
> > 次数为 $n+(n-1)+\dots+1=n(n+1)/2$，仍是 $O(n^{2})$，系数减半但阶不变。

> [!PRACTICE] 3 · 空间
> 递归计算 $n!$，递归深度是多少？空间复杂度是多少？
>
> > [!ANSWER] 看答案
> > 每层调用一次，深度 $n$，栈帧 $n$ 个，$S(n)=O(n)$；时间上每层常数次乘法，$T(n)=O(n)$。

## 严格表述

设 $T(n)$ 为算法在规模 $n$ 下的基本语句执行次数。若存在正常数 $c$ 与 $n_0$，使当 $n\ge n_0$ 时 $0\le T(n)\le c\,g(n)$，则记 $T(n)=O(g(n))$；若 $T(n)\ge c\,g(n)$，记 $T(n)=\Omega(g(n))$；若二者同时成立，记 $T(n)=\Theta(g(n))$。若对任意 $c>0$ 都存在 $n_0$ 使 $n\ge n_0$ 时 $T(n)<c\,g(n)$，则记 $T(n)=o(g(n))$。多项式 $T(n)=a_k n^{k}+\dots+a_0$（$a_k>0$）满足 $T(n)=\Theta(n^{k})$。空间复杂度按算法运行期间除输入外额外占用的最大存储单元数计，递归算法的空间开销至少与递归深度同阶。
