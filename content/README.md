# 讲次正文写作规范

正文是纯 Markdown。所有版式（导语、卡片、练习、折叠答案、表格边框）都由导入器与站点样式自动生成，**作者不写任何 HTML class**。

唯一例外是图示：需要内联 `<svg>` 时可以直接写 `<figure>`（部分导入时开启了原始 HTML）。

## 一、文件与地址

```
content/lessons/<subject>/<unit>/<NN-slug>.<lang>.md
```

例如 `content/lessons/la/u01/01-matrix-mult.zh.md` 对应地址：

```
/zh/read/la/u01/1
```

地址只由 `学科 / 单元 / 序号` 决定。改标题、改文件名都不影响链接；只有改动 `order` 或插入新讲次才会改变序号。

## 二、frontmatter

```yaml
---
slug: "matrix-mult"      # 必填，全局唯一
subject: "la"            # 必填，需在 subjects.yaml 中存在
unit: "u01"              # 必填，需在 subjects.yaml 中存在
order: 1                 # 讲次序号，决定地址与排序
mode: "mastery"          # 必填，mastery / applied / literacy
lang: "zh"               # 必填，zh / en
title: "矩阵乘法"         # 必填
subtitle: "行与列握手的那个动作"
kicker: "第 1 讲 · 线性代数 · 专业模式"
minutes: 16
meta: ["阅读 16 分钟", "需要 初等数学", "掌握级"]
concepts: ["matrix", "la"]   # 需在 concepts.yaml 中存在
prereq: ["elem"]
related: ["la", "matrix"]
---
```

**不要写** `prev_title` / `prev_href` / `next_title` / `next_href`。上一讲、下一讲由导入器按 `(学科, 模式, 语言)` 分组、按 `(单元序号, 讲次序号)` 排序自动推导；第一讲与最后一讲自动回落到课程路线页。

## 三、分节：`##`

一个二级标题就是一节，顺序、编号、锚点全部自动生成：

```md
## 本讲目标

正文……

## 三行回顾

- 第一条
- 第二条
```

- 编号自动为 `01`、`02`……，锚点为 `sec-1`、`sec-2`……
- 左侧目录自动同步，不需要手动登记
- 第一节的第一段自动变成导语（大号衬线 + 左侧蓝线），无需标记
- 某一节顶层的无序列表自动变成带编号的"回顾"清单
- 至少需要一个 `##`，否则导入报错

## 四、卡片：提示块语法

卡片统一用 GitHub 风格的提示块（alert）。**第一行在行首写类型和标题，后续每一行都以 `>` 开头**：

```md
> [!TYPE] 标题
> 正文
```

导入器逐行扫描：只认行首的 `>`，不依赖 HTML、不依赖空行分隔，也不要求卡片前后留空行。

### 五种卡片

| 类型 | 渲染结果 | 视觉 | 默认折叠 |
| --- | --- | --- | --- |
| `[!NOTE]` | `<aside class="callout">` | 浅底提示条，左侧蓝色竖线 | 否 |
| `[!MYTH]` | `<div class="myth">` | 误解卡片，标题前自动加 `✕` | 否 |
| `[!PRACTICE]` | `<div class="ex">` | 练习卡片，标题为小号等宽蓝字 | 否 |
| `[!ANSWER]` | `<details class="answer">` | 折叠答案，`+` / `−` 切换 | 是 |
| `[!FORMAL]` | `<details class="formal">` | 虚线框折叠块，用于严格表述 | 是 |

### 五条规则

1. **`[!NOTE]` 不显示标题**：模板只输出正文，写在方括号后的文字会被直接丢弃。需要标题就换用其他四种。
2. **另外四种的标题必填**：`[!MYTH]` / `[!PRACTICE]` 的标题落在 `<b>` 里，`[!ANSWER]` / `[!FORMAL]` 落在 `<summary>` 里；留空会渲染出一行空的加粗字或一个空折叠条。
3. **卡片的第一行必须顶格**：`> [!MYTH] …` 前面有缩进就退化成普通引用，卡片不生成；卡片开始之后的续行则允许缩进。
4. **卡片在第一个不以 `>` 开头的行结束**，空行也算。所以卡片内部的空行必须写成单独一个 `>`。
5. **嵌套一层多一个 `>`**：`> [!PRACTICE]` 里嵌 `> > [!ANSWER]`，再往下一层就写 `> > >`。

类型名区分大小写且不能带空格：`[!MYTH]` 有效；`[!myth]`、`[! MYTH]`、`[!TIP]`、`[!WARNING]` 都只会按普通引用原样显示。

### 示例：提示条与误解卡

```md
> [!NOTE]
> S = T ⇔ S ⊆ T 且 T ⊆ S

> [!MYTH] 空集没有用。
> 它是任何集合的子集，也是集合运算的边界情形；没有它，交集可能无结果，子集计数会少一个情形。
```

### 示例：练习与折叠答案

练习卡片里再嵌一层 `ANSWER`，只需在内层多写一个 `>`：

```md
> [!PRACTICE] 1 · 判断
> ∅ ⊆ {1, 2}？{1} ∈ {1, 2}？
>
> > [!ANSWER] 看答案
> > 是；否，{1} 是集合不是元素。
```

注意中间那行单独的 `>`：卡片内部的空行必须写成 `>`，完全空行会提前结束卡片。

### 示例：严格表述

放在一节末尾，默认折叠：

```md
> [!FORMAL] 严格表述
> 矩阵乘法是线性映射的复合……
```

### 卡片内部可以放什么

卡片正文会再走一遍 Markdown 渲染，段落、列表、行内代码、$公式$、$$独立公式$$ 都可用；再嵌一层卡片也可以：

```md
> [!PRACTICE] 2 · 手算
> 已知：
>
> - $A$ 是 $4 \times 2$
> - $B$ 是 $2 \times 5$
>
> 求 $AB$ 的形状。
>
> > [!ANSWER] 看答案
> > $4 \times 5$。
```

两条限制：表格宽度在卡片里不够用，建议改成列表或分段；卡片内不要写 `##`，它不会进入左侧目录，只会变成卡片内部的大标题。

### 常见错误

| 现象 | 原因 | 改法 |
| --- | --- | --- |
| 卡片只有第一段，后半段跑到卡片外 | 卡片中间写了完全空行 | 空行写成一行 `>` |
| 答案没有折叠，直接露在练习里 | `[!ANSWER]` 与 `[!PRACTICE]` 同层 | ANSWER 的每一行前多写一个 `>` |
| 页面上出现字面量 `> [!MYTH]` | 行首有缩进，或类型写成小写、带空格 | 顶格写，类型全大写 |
| 标题位置多出一行空的加粗字 | `[!MYTH]` / `[!PRACTICE]` 没写标题 | 补标题，或改用 `[!NOTE]` 把说明写进正文 |
| 标题整段消失 | 用了 `[!NOTE] 标题` | 标题移进正文，或换用其他类型 |

### 完整骨架

一节的卡片通常按「误解 → 练习 → 严格表述」排列，可直接复制：

```md
## 三个常见误解

> [!MYTH] 写成一句会被相信的错误说法。
> 用一两句给出反例或纠正。

> [!PRACTICE] 1 · 小标题
> 题干，可以带 $公式$。
>
> > [!ANSWER] 看答案
> > 答案。

> [!FORMAL] 严格表述
> 定义、定理或公式的完整陈述。
```

`[!FORMAL]` 一般放在一节最末，`[!ANSWER]` 只出现在 `[!PRACTICE]` 内部。

## 五、其余 Markdown

| 写法 | 结果 |
| --- | --- |
| 普通段落 | 正文段落 |
| `- 项目` | 普通列表（顶层则自动变回顾清单） |
| 管道表格 | 自动套圆角边框容器，可横向滚动 |
| `$x^2$` | 行内公式，KaTeX 渲染 |
| `$$\int_0^1 x\,dx$$` | 独立公式，整行居中 |
| `**粗体**`、`*斜体*`、`` `代码` `` | 常规 |
| `` ``` `` 围栏代码块 | 常规；但块内不要出现行首 `##`，会被误判为分节 |

表格示例（单元格内的竖线写成 `\|`）：

```md
| 左矩阵 | 右矩阵 | 能乘吗 |
| --- | --- | --- |
| $2 \times 3$ | $3 \times 4$ | 能 |
| $3 \times 2$ | $3 \times 4$ | 不能 |
```

## 六、不要再写的东西

| 旧写法 | 现在 |
| --- | --- |
| `<!-- section: id \| 01 \| 标题 -->` | 删除，改用 `## 标题` |
| `<p class="lead">` | 删除，首段自动成为导语 |
| `<ul class="recap">` | 删除，改用 `- ` 列表 |
| `<div class="myth"><b>…</b><span>…</span></div>` | 改用 `> [!MYTH] 标题` |
| `<div class="ex">` + `<details>` | 改用 `> [!PRACTICE]` + `> > [!ANSWER]` |
| `<details class="formal">` | 改用 `> [!FORMAL]` |
| `<div class="table-wrap"><table>…` | 改用管道表格 |
| `<span class="formula-line">` | 改用 `$$…$$` |
| `prev_*` / `next_*` | 删除，自动推导 |

## 七、导入与校验

```bash
cd server
.venv/bin/python manage.py import_content   # 可重复执行，覆盖而非重复
.venv/bin/python manage.py test             # 校验接口与小节数量
```

导入时会报错的情况：缺少必填 frontmatter、指向不存在的单元、引用了未定义的概念、正文没有 `##` 小节。
