# 扫描版教材 → Markdown 转换器

`资料/` 下的 PDF 全部是无文字层的扫描件（297 本、125,550 页），因此转换流程是
「页面渲染 → OCR 识别正文 → 几何版面分析 → 公式/插图按原图像素裁切」，而不是普通的
PDF 文本抽取。

## 产物布局

与 PDF 同目录：

```
资料/001.组织学与胚胎学/
├── 《组织学与胚胎学》李继承.pdf
├── 《组织学与胚胎学》李继承.md
└── 《组织学与胚胎学》李继承.assets/
    ├── p0004-fig01.png
    ├── p0020-eq01.png
    └── ...
```

Markdown 结构：`# 书名` → 每页 `<!-- page N -->` 注释 → `## 章 / ### 节` →
正文段落 → `![公式](...)` / `![图 x.x ...](...)` + 图注。

## 为什么公式与插图用图片

扫描件的公式经 OCR 后必然出错（实测 `ln x`→`Inr`、`f(x)`→`げ(a)`）。为保证「公式正确」，
公式行、图、表一律从原书页面按坐标裁切为 PNG 嵌入，像素级保真、不做重排；正文才用 OCR 文本。
代价是公式不可检索、不可编辑。

## 用法

```bash
# 单本（--max-pages 用于试跑）
python3 tools/pdf2md/build.py "资料/xxx/yyy.pdf"

# 按《主教材绑定表.md》批量转换，25 分钟一批
python3 tools/pdf2md/batch.py --minutes 25

# 先看匹配结果
python3 tools/pdf2md/batch.py --dry-run
```

OCR 使用 macOS Vision（`ocr` Swift 程序），需要沙箱外执行；`crop` 负责按 JSON 坐标裁图。
两个二进制由同目录的 `ocr.swift`、`crop.swift` 编译：

```bash
swiftc -O ocr.swift -o ocr && swiftc -O crop.swift -o crop
```

## 已知限制

- 正文是机器识别结果，存在同音/形近字错误（如「连续」→「连绞」），引用前需校对。
- 行内公式仍留在正文文本中，OCR 可能失真；独立公式已改用图片。
- 跨页表格、双栏排版尚未专门处理；表格按整块图片保留。
- 扫描页的页眉页脚会按位置与内容规则剔除，偶有漏网。
- 97 本匹配到的主教材共约 46,983 页，当前吞吐约 110 页/分钟，全量约需 7–8 小时机时。
